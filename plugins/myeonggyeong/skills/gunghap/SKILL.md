# 명경(明鏡) · 연애 궁합

두 사람의 생년월일시 → fate-js `matchSheet`로 계산 → 해석 가이드로 이야기화 → **1차: 짧은 핵심 궁합(자동)** → **2차: 궁금한 장만(요청 시)**.

## 0. 원칙 (위반 금지)

- 시트에 없는 사실을 지어내지 않는다. 모든 해석은 계산된 관계 사실(合/生/沖·배우자성·용신 공급·신살 방향)에 근거한다.
- **점수(궁합 %·별점) 금지.** matchSheet는 점수가 아니라 관계 사실을 낸다. "몇 점" 대신 "어디서 끌리고 어디서 부딪히는지"를 말한다.
- **한쪽을 탓하지 않는다.** 관계는 두 사람의 상호작용 — "이 사람이 문제"가 아니라 "이 조합에서 이런 결이 생긴다".
- 헤어져라·만나라 단정 금지. 궁합은 운명 선고가 아니라 **다루는 법**을 알려주는 것.
- **해석이 본문, 설명은 각주** ([[saju]]와 동일): 모든 문단 = ① 두 사람은 이런 조합 ② 그래서 관계에서 이런 일이 생긴다 ③ 그럴 땐 이렇게 하라. 글자·合沖 얘기는 문단 끝 괄호 근거 한 줄로.
- **쉬운 말·톤 레이어**도 [[saju]]와 동일(용어는 쉬운 이름 먼저, 말투는 안내인 캐릭터 설정).

## 1. 입력 수집

두 사람 각각의 생년월일(양력 기준), 태어난 시각(모르면 시간 모름), 출생 도시(기본 Asia/Seoul), 성별. 그리고 호칭 두 개(예: "나"·"상대", 또는 이름). **누가 요청자 본인인지** 확인하고, 상대 정보는 본인이 아는 만큼만 — 없는 정보로 채우지 않는다.

## 2. 계산

```bash
mkdir -p /tmp/mg-report && cd /tmp/mg-report
npm init -y >/dev/null 2>&1
npm install --ignore-scripts github:greyfolk99/fate-js
```

```bash
node --input-type=module -e "
import { bazi, matchSheet, formatMatchSheet } from 'fate-js';
const A = { bazi: bazi({ year:Ay, month:Am, day:Ad, hour:Ah, minute:Amin, timezone:'Asia/Seoul' }), gender:'female' };
const B = { bazi: bazi({ year:By, month:Bm, day:Bd, hour:Bh, minute:Bmin, timezone:'Asia/Seoul' }), gender:'male' };
const m = matchSheet(A, B);
console.log(formatMatchSheet(m));
console.log(JSON.stringify(m));
"
```

시트 구조: `lenses`(合 끌림·정 / 生 보완·상생 / 沖 관계온도), `facts`, `judgments`(교차·병존·쟁합 등). 각 항목은 A/B 어느 기둥에서 왔는지(글자·자리) 표기돼 있다 — 근거로 그대로 쓴다.

해석 원칙이 필요하면(전문 서술 전 1회):
```bash
curl -s https://raw.githubusercontent.com/greyfolk99/fate-js/main/docs/interpretation-guide-2026-09.md
```

## 3. 1차 출력 — 핵심 궁합 (자동, 짧게, 30줄 이내)

"두 사람은 이런 조합 → 관계에서 생기는 일 → 다루는 법" 순서. 합충 용어로 시작하지 않는다.

1. **이야기 제목** — 두 사람 관계의 핵심 이미지로. 예: "끌림은 세고, 온도는 조심스러운 사이".
2. **어떤 조합인지** (3~4문장) — 서로 무엇에 끌리고(合), 무엇을 채워주고(生), 어디서 부딪히는지(沖)를 일상 언어로. 누가 누구에게 무엇을 주는지 방향까지.
3. **이 관계에서 좋은 것 2~3개** — 서로를 끌어당기고 보완하는 지점(合·生·용신 공급). 한 줄씩.
4. **조심할 것 1~2개** — 온도가 튀는 지점(沖·害·刑)을 담담하게 + 다루는 법 한 줄.
5. **근거 한 줄** — 괄호로: "(근거: 六合 2·三合 金·用神 A←B 金水 공급·六害 일지 — 자세한 건 아래 장에서)"
6. **목차 메뉴** — 아래 장 목록: "번호를 말하면 그 장을 풀어드려요."
7. **맺음 한 줄** — "궁합은 점수가 아니라 다루는 법이에요. 모든 문장엔 계산된 근거가 붙어요 — 명경(明鏡)." + https://greyfolk99.github.io/myeonggyeong/

## 4. 목차 (장을 열 때 하위 항목은 체크리스트 — 빠뜨리지 않는다)

1. **끌림 — 서로를 당기는 것(合)** · 천간합·육합·삼합/방합·암합이 만드는 정서적 끌림 · 어느 자리끼리인지
2. **보완 — 채워주는 것(生)** · 오행 상보 · 배우자성 공급(누가 배우자 자리를 채우나) · 용신·조후를 서로 공급하는지 · 방향(A←B / B←A)
3. **온도 — 부딪히는 것(沖)** · 충·형·해·파가 어디서 · 관계의 긴장이 나오는 자리 · 다루는 법
4. **배우자 자리 — 일지끼리** · 배우자궁의 만남 · 십이운성 교차(서로에게 어떤 기운으로 앉나) · 공망 교차
5. **신살의 인연** · 서로에게 도는 귀인·도화·역마 등 · 담담하게
6. **종합 — 이 관계를 다루는 법** · 강점을 살리고 온도를 낮추는 실제 조언

관상 궁합(얼굴 실측 대조)은 준비 중 — 지어내지 않는다.

## 5. 장 진행 (요청 시)

- 번호를 말하면 그 장을 하위 항목 전부 포함해 "조합 → 관계 장면 → 다루는 법" 순서로 푼다. 소제목으로 빠짐이 보이게.
- 이미지 생성이 가능한 환경이면 장마다 웹툰 컷 1장(두 캐릭터가 그 장면을, 텍스트는 이미지에 넣지 않음).
- 한 장이 끝나면 "다음으로 볼 장 있어요?"로 잇는다.

## 6. 전체 궁합 리포트 파일 (요청 시에만)

"전체 리포트"를 원하면 두 사람 정보와 위 장들을 한 HTML 파일로 저장한다(`myeonggyeong-gunghap-<A>-<B>.html`). 전용 템플릿이 아직 없으면, [[saju]]의 톤·구조를 따라 궁합용으로 구성해 만든다. 점수·순위 표기는 넣지 않는다.
